# Stitch 전달용 최종 프롬프트

투자사업 공사비 적정성 검토 MVP의 핵심 검토 워크스페이스를 만들어줘.

이 결과는 완성된 운영 서비스가 아니라 Next.js에 연결할 수 있는 화면 설계와 시작 코드다. 실제 API, PostgreSQL, 파일 업로드, 로그인, 승인 저장은 기존 FastAPI/Next.js 코드에서 연결한다.

## 화면 목표

가장 중요한 화면은 `프로젝트 전체 통합 검토 큐 + 우측 원본 근거 패널`이다. 사용자가 검토 대상, 경고 사유, 원본 위치, 승인 상태를 한 화면에서 이해할 수 있어야 한다.

## 확정 디자인 방향: A + B + C 조합

전역 기본은 `Evidence Navy` 시안(A)을 사용한다. 대량 표·관리자 화면은 `Government Neutral` 시안(B)의 정보 밀도와 오류 표현을 사용하고, 도면 변경 화면은 `CAD Review Workspace` 시안(C)의 기준/변경 나란히 비교 방식을 사용한다. 함께 제공한 `option_a_evidence_navy.png`, `option_b_government_neutral.png`, `option_c_cad_workspace.png`를 시각적 참고로 사용해줘.

- PC용 1440px 기준, 1280px에서도 가로 스크롤 없이 동작
- 한국어 기업 업무 화면
- 기본 색상: 네이비 `#102A43`, 청록 `#56C7BA`, 밝은 표면 `#FFFFFF`, 배경 `#F4F7F8`
- 대량 표·관리자 화면 보조: 진회색 `#1F2937`, 파랑 `#2563EB`, 배경 `#F8FAFC`
- 도면 변경 강조: 주황 `#E07A25`, 보조 배경 `#FFF0DC`
- 높음 경고: 어두운 빨강 계열, 일반 경고: amber, 참고/대기: 회색·파랑
- 초록은 최종 확정에만 사용하고 승인 전 후보에는 사용하지 않음
- 글꼴: `Noto Sans KR` 우선, 파일 해시·좌표·도면번호·규칙 ID에는 `Roboto Mono`
- 아이콘: Lucide 계열의 선형 아이콘을 사용하고 아이콘만으로 상태를 전달하지 않음
- 기본 모서리 8px, 상세 패널 10~12px. 모든 카드를 과도한 pill 형태로 만들지 않음
- WCAG 2.2 AA 수준의 대비를 목표로 하며 텍스트·아이콘·테두리로 상태를 중복 표현
- 표와 상세 근거 패널 우선
- 장식적인 그래프·큰 금액 카드·가짜 자동판정 문구는 최소화
- 실제 API 연결 대신 명확한 mock 데이터 구조와 TODO 연결 지점을 사용

## 서비스 컨텍스트

- 서비스명: `투자사업 공사비 적정성 검토`
- 기본 프로젝트: `광양5 사무동`
- 계정: `pfc391` 공사부서, `pfe391` 설계부서, `pfp391` 구매부서, `pfm391` 마스터
- 범위 계층: 프로젝트 → 건물 → 공사/공종 → 내역 항목
- 상단에 현재 사용자·부서·프로젝트·건물·공사/공종·자료 회차·Rev. 필터를 고정 표시
- 설비 이상탐지 서비스로 표현하지 않음

## 레이아웃

### 왼쪽 240px 사이드바

- 프로젝트 현황
- 통합 검토 큐
- 도면 변경
- 수량·산식·금액
- 신규내역 단가
- 승인 대기열
- 검토 이력
- 검토 챗봇

### 상단 64px 헤더

- 현재 사용자와 부서
- 프로젝트 `광양5 사무동`
- 건물 전체/선택
- 공사·공종
- 자료 회차와 Rev.
- 알림 및 도움말

### 중앙 메인 영역

1. 작은 요약 카드: 검토 대기, 높음 경고, 추가자료 요청, 공사/설계/구매 승인 대기
2. 요약 카드는 승인 전 금액을 확정 합계처럼 강조하지 않음
3. 통합 검토 큐 테이블
4. 행을 클릭하면 우측 420px 상세 근거 패널 오픈

## 통합 검토 큐

컬럼은 다음과 같다.

- 심각도
- 검토 대상
- 공종
- 건물/층
- 상태
- 현재 승인 단계
- 원본 위치
- 신뢰도
- 최근 변경 시각

상태 배지는 다음을 사용한다.

- 검토 대기
- 검토 중
- 승인
- 수정 요청
- 반려
- 추가자료 요청
- 적용 후보
- 적용 보류
- 확정 전

승인 전 수량·금액·단가는 반드시 `후보값`, `승인 대기`, `확정 전` 배지를 함께 표시한다. 초록색 완료값이나 확정 합계처럼 표현하지 않는다.

## 우측 상세 근거 패널

제목은 `왜 검토가 필요한가`로 한다.

다음을 표시한다.

- 경고 사유
- 적용 규칙 ID와 버전
- 상태 배지
- 원본 파일명·SHA-256·자료 유형·기준일
- 엑셀인 경우 시트명·행·셀
- 도면인 경우 도면번호·시트·Rev.·페이지·좌표·GRID/ZONE
- 원본값과 표준화값 비교
- 도면 변경 후보 → 수량산출서 → 내역서 → 단가 후보 연결
- 신뢰도는 `근거 강도`라고 표시하고 확정 여부로 표현하지 않음
- 관련 승인 이력과 담당자 의견

하단 버튼:

- 원본 근거 열기
- 검토 화면으로 이동
- 추가자료 요청

## 유형별 상세

### 도면 변경

- 기준/변경 도면 썸네일
- 도면번호, 시트, Rev.
- 동/층/공간, GRID/ZONE
- 변경 후보 설명
- 수량산출서 행과 내역서 항목 연결 후보
- 연결이 없을 때 `불가`가 아니라 `연결 후보` 또는 `추가 확인 필요`

### 수량·산식·금액

- 산식 원문
- 재계산값
- 보고값
- 차이율·차이금액
- 단위·규격 불일치
- 원본 시트·행·셀

### 신규내역 단가

후보 순서를 다음과 같이 보여준다.

1. 동일 프로젝트 다른 건물의 승인 참고단가
2. 공식 조달청 CSV·표준시장단가
3. 조달청 API 결과

각 후보에 출처, 기준일, 적용조건, 조회 상태를 표시한다. 자동 적용 버튼은 만들지 말고 `적용 후보`, `적용 보류`, `구매부서 검토`만 제공한다.

### 승인

- 공사 → 설계 → 구매 단계 타임라인
- 담당자와 의견
- 승인·수정 요청·반려·추가자료 요청 상태
- 현재 단계가 아니면 승인 버튼 비활성화
- 마스터의 단계 우회는 사유 입력을 요구

## 일괄 승인

승인 대기열에서 개별 처리와 선택 일괄 처리를 지원한다.

일괄 처리 모달에는 실행 전에 다음을 표시한다.

- 선택 항목 수
- 필수 근거 누락 수
- 상태 충돌 수
- 현재 사용자에게 허용되지 않는 항목 수

실행 후에는 전체 성공/실패가 아니라 항목별 성공·실패·실패 사유를 표시한다.

## 필수 상태 화면

- loading: 테이블 skeleton과 전처리 진행률
- empty: `현재 범위에 검토 대상이 없습니다`와 필터 초기화
- error: 오류 코드·요청 ID·재시도 버튼
- permission denied: 필요한 부서 권한 안내
- stale version: `최신 회차를 다시 불러오세요`
- original evidence missing: 원본 파일·시트·행·도면 위치 확인 요청
- procurement error: 인증 실패·권한 오류·검색 결과 없음·타임아웃을 구분
- batch partial failure: 성공/실패 행별 결과

## 챗봇

프로젝트·건물·공사 범위가 고정된 읽기 전용 근거 검색 도우미로 만든다.

- 답변마다 원본 근거 링크와 신뢰도를 표시
- 근거가 없으면 `현재 자료에서 확인되지 않습니다` 표시
- 승인·반려·단가 확정·원본 수정 요청은 실행하지 않고 관련 화면으로 이동
- 추천 질문: `높음 경고만 보여줘`, `A-101 Rev.04 변경 후보의 근거는?`, `42행 수량 차이는 왜 발생했어?`

## 샘플 데이터

- 프로젝트: 광양5 사무동
- 공사: 기계실 배관 공사
- 도면: A-101 / Rev.03 → Rev.04 / 2층 기계실 / GRID B-4
- 수량산출서: 수량산출서_예시.xlsx / 수량 시트 / 42행
- 상태: 수량 검토 대기, 설계 근거 확인 대기, 단가 적용 보류
- 단가 후보: 동일 프로젝트 타건물 참고, 공식 표준시장단가, 조달청 API 결과 없음

실제 백엔드 연결이나 운영 파일 다운로드가 구현된 것처럼 표현하지 말고, Next.js API 연결 위치를 TODO 또는 mock service로 분리해줘.
