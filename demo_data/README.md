# 사무동 데모 테스트 자료

광양5 사무동의 업로드·전처리·수량 검토·변경 신규내역 단가 검토 흐름을 재현하기 위한 가상 자료입니다. 실제 프로젝트 원본을 덮어쓰지 않도록 `demo_data` 폴더에만 보관합니다.

## 업로드 순서

1. `demo_office_baseline_estimate.xlsx`를 `내역서`, `기준`, 건물 `사무동`으로 등록합니다.
2. `demo_office_baseline_quantity.xlsx`를 `수량산출서`, `기준`, 건물 `사무동`으로 등록합니다.
3. `demo_office_changed_estimate.xlsx`를 `내역서`, `변경`, 건물 `사무동`으로 등록합니다.
4. `demo_office_changed_quantity.xlsx`를 `수량산출서`, `변경`, 건물 `사무동`으로 등록합니다.
5. 업로드가 끝나면 전처리 실행이 완료될 때까지 기다린 뒤 `/quantities`에서 자료 세트와 공종을 선택합니다.
6. 신규내역 단가 매칭을 확인하려면 로컬 백엔드를 재시작한 뒤 `/prices`에서 `참고 단가 저장`을 실행합니다. `demo_price_references.csv`는 타건물 참고자료이며 자동 확정되지 않습니다.

## 확인할 결과

- 제목 행 `0301. 방수공사`는 수량이 없는 구분 행이므로 검토 항목으로 생성되지 않습니다.
- `보안동` 행은 사무동 범위 밖이므로 사무동 수량·단가 검토에 섞이지 않습니다.
- 기준자료에서 방수 수량은 `480`, 변경자료 내역서 수량은 `520`, 변경자료 수량산출서 수량은 `500`입니다. 변경 검토에서 내역서와 산출서 차이가 표시되어야 합니다.
- 철골보는 변경 내역서가 `7.0 + 5.6 = 12.6 TON`, 변경 수량산출서가 `7.1 + 5.5 = 12.6 TON`으로 여러 원본 행의 합계를 비교하는 사례입니다.
- `흡음패널`은 변경자료에만 있는 사무동 신규내역이므로 `/prices`에서 단가 검토 후보로 생성되어야 합니다.
- `기존 보온재 철거`의 수량 0은 삭제 후보이며 신규 단가 후보로 생성되지 않아야 합니다.
- 수량이 비어 있고 산식만 있는 `산식만 있고 원본수량 없음` 행은 원본 근거 확인 경고로 남아야 합니다.

필요하면 프로젝트 루트에서 다음 명령으로 동일한 XLSX를 다시 생성할 수 있습니다.

```powershell
& 'C:\Users\LG\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe' demo_data\build_demo_workbooks.mjs
```

이 자료는 실제 공사비나 승인값이 아닌 전처리·검토 동작 확인용입니다.
